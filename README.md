# 轻传 · LightDrop

手机 ↔ 平板 局域网直传。不经过任何服务器，不耗流量，安装包 123 KB，零第三方依赖（纯 Android 框架 API），最低支持 Android 6.0。

---

## 一、它解决什么

- 平板不装微信（省下几个 G），文件照样能到手
- 不经过云端、不限速，速度取决于路由器（一般 10–30 MB/s）
- 原生界面，选完文件点一下就发，不用开浏览器、不用扫码登录

## 二、安装

1. 把 `LightDrop-1.3.0.apk` 分别装到**手机**和**平板**（同一个包，两端功能一样）
2. 首次安装需允许「安装未知来源应用」
3. 两台设备连**同一个 Wi-Fi**；没有路由器时，用平板开热点、手机连上，同样可用

## 三、从微信发文件（重点）

**先说清楚一件事**：微信不允许第三方 App 出现在它的分享菜单里。长按聊天文件，你能看到的只有「转发 / 收藏 / 删除 / 更多」，没有「分享到其他应用」。
这是微信的产品设计，任何 App 都绕不过去。所以「长按文件 → 直接发到平板」做不到。

能做的是下面三条路，按顺手程度排序：

| 方式 | 操作步骤 | 适合 |
|---|---|---|
| **A. 保存到手机 + 最近文件**（最稳） | 微信长按文件 →「保存到手机」→ 回轻传点「发送文件」→ 顶部第一个就是它 → 点选 → 发送 | 日常最常用 |
| **B. 用其他应用打开** | 微信长按文件 →「用其他应用打开」→ 选「轻传」→ 点一下「发送到 平板名」 | 微信支持该文件类型时最快 |
| **C. 浏览器直传**（兜底） | 手机浏览器打开平板显示的地址（如 `http://192.168.1.23:46000`）→ 选文件 → 上传 | 装不了 App / 发现不了设备 |

### 方式 A 的细节

第一次点「发送文件」时，App 会请你开一个权限：**所有文件访问**。

> **这里有个必须讲清的系统限制**：微信聊天文件的真实位置是
> `/sdcard/Android/data/com.tencent.mm/MicroMsg/…`，从 Android 11 起这个目录被系统锁死，
> **任何第三方应用都读不到**——申请「所有文件访问」也读不到，这不是权限没给够。
> 文件管理器、清理工具同样打不开。
>
> 轻传能读的是微信另外几个**可读**位置：
> `Download/`、`tencent/MicroMsg/`、`Android/media/com.tencent.mm/`、`DCIM/WeChat`。
> 也就是说，**聊天里没点过「保存」的原件扫不到**；点过保存的，几秒后就会出现在列表里。
> 想直接发原件，走方式 B。

列表按时间倒序，微信来源的文件会标「微信」，覆盖最近 30 天。点一下选中，可以多选，底部点「发送到平板」。

### 方式 C 的细节

平板「接收文件」页会显示 `192.168.1.23` 这类地址。手机浏览器地址栏输入 `http://` 加上这串（端口不是 46000 时也要带上，如 `http://192.168.1.23:46001`），会打开一个上传页，选文件点「开始发送」即可。文件同样落到平板 `Download/轻传`。

这条路不需要装 App，适合临时给别人的平板传一次。

## 三·五、连不上怎么查

按顺序试，基本三步内能定位：

1. **先看平板**：打开轻传，「接收文件」开关是开的，页面上有一行 `192.168.1.5:46000` 这样的地址。
   主界面也会直接显示「接收中 · 地址」。看不到就点开关。
2. **点平板上的「连不上？点这里自检」**：它会本机连自己一次。
   - 自检显示「正常」→ 平板没问题，是两台设备之间的网络不通（见第 3 步）
   - 自检显示「无响应」→ 端口被别的应用占了，关掉那个应用或重启平板
3. **网络这一层**：确认两台设备连的是同一个 Wi-Fi（不是访客网络），
   手机有「移动数据」时先关掉；路由器里若开了「AP 隔离 / 客户端隔离」，两台设备会互相看不见，需要在路由器设置里关掉。

都排查过还是不行，就用手输地址：手机端点「发送文件」页面下方的输入框，
填平板上那串 `IP:端口`，点连接。它会先握手确认，再发文件，连不上会明确告诉你「这个地址上没有轻传在监听」。

最后还有一条不依赖 App 的路：手机浏览器打开 `http://平板IP:端口`，直接在网页里选文件上传。

## 四、其他用法

- **传相册/文档/压缩包**：点「发送文件」→ 右上角「浏览…」，走系统文件选择器，可多选
- **反过来传**：手机开「接收文件」，平板选「发送文件」，逻辑对称
- **接收端可以锁屏**：开启接收后，页面可以关掉、屏幕可以锁，通知栏会有状态通知，点「停止接收」可随时关闭
- **纯文本分享**：从别的 App 分享一段文字给轻传，会自动存成 `.txt` 再发送

## 五、它是怎么传的

| 环节 | 实现 |
|---|---|
| 找设备 | ① UDP 46001 广播（重复 3 轮）② 广播无响应时，自动扫描同网段 254 个地址的 TCP 46000 端口 |
| 传文件 | TCP 46000，协议 v2：魔数 + 版本 + 文件清单 + 原始字节流 + **落盘确认** |
| 落盘 | Android 10+ 走 MediaStore（`Download/轻传`，无需存储权限）；Android 9 及以下直写公共目录 |
| 失败处理 | 接收端写完才回 1，发送端拿到确认才算成功；中断会删掉半成品文件 |
| 网页兜底 | 同一个 46000 端口同时识别 HTTP 请求，浏览器打开即上传 |

**为什么要加落盘确认**：v1.1.0 的发送端把数据推完就报「发送成功」，但接收端可能还在写盘或已经失败，于是出现「显示成功、平板里没有」。v1.2.0 改成接收端写完文件后回执，发送端等到回执才报成功，失败会显示具体原因。

**后台接收**：接收端是前台服务（`dataSync` 类型），持有 Wi-Fi 高性能锁，传输期间额外持 CPU 唤醒锁。代价是常驻通知 + 待机耗电略增；国产 ROM 还需在系统设置里允许「自启动 / 后台运行」。

## 六、连不上怎么排查

按这个顺序试，基本能定位：

| 现象 | 原因 | 处理 |
|---|---|---|
| 搜不到设备 | 两台不在同一 Wi-Fi | 手机连平板开的热点，或都连同一个路由器（别用访客网络） |
| 搜不到设备 | 路由器开了 AP 隔离 | 关掉路由器的「AP 隔离 / 客户端隔离」；或直接用方式 C 的网页上传 |
| 搜不到设备 | 平板接收服务没起来 | 平板「接收文件」页看开关是否打开、地址有没有显示；没有就关掉再开一次 |
| 搜到了但连不上 | 端口被占 | 接收端会依次尝试 46000–46009，页面显示实际端口；按显示的地址手输 |
| 传一半断了 | 平板息屏被系统清理 | 给轻传开「自启动 / 后台运行 / 电池不优化」 |
| 显示失败 | 看提示文字 | 现在会区分「连不上」「超时」「对方保存失败」并显示具体原因 |

发送页底部可以手动输入 IP（支持 `192.168.1.23` 或 `192.168.1.23:46001`）。

## 七、自动检查更新

App 每次启动静默查一次（24 小时内不重复），有新版弹窗提示，下载完直接调起安装。

**默认更新源已内置**：`coolflower1984/lightdrop`，装完即用。仓库：<https://github.com/coolflower1984/lightdrop>

**发版**

```bash
printf '1.2.1\n4\n' > VERSION        # 第一行版本名，第二行 versionCode（必须递增）
git add -A && git commit -m "xxx"
git tag v1.2.1 && git push origin main --tags
```

推完约 30 秒，Actions 自动编译签名并挂到 Releases。

> **versionCode 必须递增**，否则已安装的旧版不会认为是新版本。
> 它是 `VERSION` 文件第二行，优先级高于 git 提交数。

签名证书不在仓库里（避免公开私钥），CI 通过 `KEYSTORE_BASE64` / `KEYSTORE_PASS` 两个 Secrets 还原。本地留了一份在 `../LightDrop-signing/lightdrop.jks`，丢了就再也无法覆盖升级。

## 八、自己构建

不需要 Android Studio / Gradle，脚本直接调 aapt2 / javac / d8 / apksigner：

```bash
export ANDROID_HOME=/path/to/android-sdk   # 需 platforms;android-34、build-tools;34.0.0
mkdir -p keystore && cp /path/to/lightdrop.jks keystore/
./build.sh                                  # 产物在 build/LightDrop-<版本>.apk
```

版本号优先级：`VERSION_NAME` / `VERSION_CODE` 环境变量 → `VERSION` 文件 → git tag / 提交数。

## 十、已知限制

- 微信不开放分享菜单，做不到「长按文件直接发」，见第三节
- 平板接收期间建议保留通知（前台服务），否则部分 ROM 会杀进程
- 目前是单文件串行传输，尚未做断点续传
